# Migrate to Copilot SDK 1.0.1

The plugin pins `@github/copilot-sdk@^0.2.1`. CLI ≥ ~1.0.5x removed the legacy
`--headless --stdio` interface (github/copilot-cli#1606); SDK 1.0 speaks the new
protocol (v3). Result: plugin cannot connect with current CLIs (user has 1.0.60).

## Changes

- [x] `package.json`: `@github/copilot-sdk` → `^1.0.1`.
- [x] `src/copilot.ts`:
  - [x] Client options: `cliUrl` → `connection: RuntimeConnection.forUri(url)`;
        `cliPath` → `connection: RuntimeConnection.forStdio({path})`;
        `cwd` → `workingDirectory`; `githubToken` → `gitHubToken`.
  - [x] Replace removed `client.getState()`/`ConnectionState` with service-tracked state
        (same `'disconnected' | 'connecting' | 'connected' | 'error'` union, defined locally).
  - [x] `ping()` return type: `timestamp: string`, optional `protocolVersion`.
  - [x] Imports: drop `MCPRemoteServerConfig`/`MCPLocalServerConfig`, re-export
        `MCPStdioServerConfig`/`MCPHTTPServerConfig`; keep deep `dist/types` import only for
        types not exported from the package root (`ReasoningEffort`, `UserInputHandler`, ...).
  - [x] Connect-failure error message hints at `copilot update` / CLI too old.
- [x] `src/view/sessionSidebar.ts`: `session.getMessages()` → `session.getEvents()`.
- [x] Typecheck clean (`tsc -noEmit -skipLibCheck`), lint clean, `npm run build` succeeds.
- [x] Deploy to test vault and verify: connect, list models, chat, reasoning capabilities.
